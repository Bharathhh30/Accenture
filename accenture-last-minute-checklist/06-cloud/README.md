# Cloud Computing

**Assessment priority: High evidence** — cloud/cloud-security concepts appear in candidate accounts and published preparation outlines.

| Concept | One-line last-minute reminder |
|---|---|
| Cloud computing | Cloud provides on-demand network access to configurable compute, storage, and services with rapid provisioning. |
| IaaS | IaaS supplies virtualized compute, storage, and networking while the customer manages more of the OS and workload. |
| PaaS | PaaS manages the underlying platform/runtime so the customer can focus mainly on application code and data. |
| SaaS | SaaS delivers a complete provider-hosted application to the customer. |
| Public cloud | Public cloud resources are operated by a provider and shared across customers with logical isolation. |
| Private cloud | Private cloud infrastructure is dedicated to one organization, whether provider-hosted or organization-managed. |
| Hybrid cloud | Hybrid cloud integrates private/on-premises and public-cloud environments. |
| Multi-cloud | Multi-cloud uses services from multiple cloud providers, whether or not they are tightly integrated. |
| Scalability | Scalability is the ability to increase/decrease system capacity as workload requirements change. |
| Elasticity | Elasticity is the ability to adjust capacity quickly in response to changing demand. |
| Region and availability zone | A region is a geographic cloud location; availability zones are separate failure domains within a region. |
| High availability | High availability uses redundancy/failover to reduce service downtime. |
| Disaster recovery | Disaster recovery restores service/data after a major disruption and is planned around RTO and RPO. |
| RTO / RPO | RTO is the target time to restore service; RPO is the target maximum tolerable data-loss interval. |
| Shared responsibility | Provider/customer security duties differ by service model; customers still manage identities, data, and secure configuration. |
| Virtualization | A hypervisor runs multiple virtual machines on shared physical hardware. |
| Containers | Containers isolate application processes while typically sharing the host OS kernel. |
| Serverless | Serverless abstracts server provisioning/management while the customer deploys functions or services. |
| Object storage | Object storage stores data as objects with metadata and identifiers, suited to unstructured data at scale. |
| Block storage | Block storage presents raw storage volumes that can be formatted and attached to compute instances. |
| File storage | File storage provides shared hierarchical directories/files through a file protocol. |
| IAM | Identity and Access Management controls identities, roles, authentication, and permissions for cloud resources. |
| Security group / network rule | Cloud network rules allow or deny traffic to resources based on addresses, ports, protocols, and direction. |
| Encryption | Encrypt data in transit and at rest, and protect/manage keys separately with controlled access. |
| Cost model | Cloud usage is commonly metered, so right-sizing, budgets, tagging, and monitoring help control costs. |
