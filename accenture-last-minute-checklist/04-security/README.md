# Security

**Assessment priority: High evidence for basic security/cloud-security concepts** — detailed depth depends on role.

| Concept | One-line last-minute reminder |
|---|---|
| CIA triad | Confidentiality prevents unauthorized disclosure, integrity prevents improper change, and availability keeps systems usable. |
| Authentication | Authentication verifies an identity. |
| Authorization | Authorization decides what an authenticated identity may access or do. |
| MFA | Multi-factor authentication combines different factor categories: knowledge, possession, or inherence. |
| Least privilege | Grant only the minimum access necessary for the current task and duration. |
| RBAC | Role-Based Access Control assigns permissions through job/function roles. |
| Password hygiene | Use unique long passwords and an approved password manager; never share credentials. |
| Phishing | Phishing uses deceptive messages/sites to trick recipients into revealing data or taking unsafe actions. |
| Social engineering | Social engineering manipulates people rather than exploiting only technical flaws. |
| Malware | Malware is software designed to harm, spy on, disrupt, or gain unauthorized access to systems. |
| Ransomware | Ransomware blocks access or encrypts data to extort payment; protected tested backups support recovery. |
| Vulnerability and threat | A vulnerability is a weakness; a threat is a potential cause of harm that may exploit it. |
| Patching | Timely patches reduce exposure to known vulnerabilities, subject to safe testing/change procedures. |
| Symmetric encryption | Symmetric encryption uses the same secret key for encryption and decryption. |
| Asymmetric encryption | Asymmetric cryptography uses a public/private key pair for functions such as key exchange or digital signatures. |
| Hashing | A cryptographic hash is a one-way digest used for integrity and, with suitable salted schemes, password verification. |
| Digital signature | A digital signature uses private-key signing and public-key verification to support integrity and signer authenticity. |
| TLS | TLS protects data in transit and authenticates a server using certificates; it does not secure a compromised endpoint. |
| Encryption at rest | At-rest encryption helps protect stored data if storage is accessed without the needed key. |
| Firewall vs IDS/IPS | A firewall enforces traffic rules; IDS detects suspicious activity; IPS can block/prevent detected activity inline. |
| Secure configuration | Remove defaults, disable unnecessary services, restrict access, and apply approved baseline settings. |
| Backup rule | Keep backups access-controlled, separated from ordinary writes, and regularly test restoration. |
| Incident response | Identify, report, contain, investigate, recover, and learn from security incidents using the approved process. |
| Data classification | Handle data according to sensitivity, retention, sharing, and regulatory requirements. |
